# Cross-assessment synthesis and whole-person map

## Purpose
Combine validated assessment results with interviews, behavioral episodes, work samples, observer feedback and longitudinal outcomes to form a revisable human map. Synthesis is construct-by-construct, not a vote among labels.

## Assessment registry and provenance
For every result, preserve instrument name/version, intended construct, date, administration context, scoring method/provenance, norm group if available, source type, consent, limitations and raw/source reference. Distinguish an actual scored result from a qualitative summary or an unscored online quiz. Never reconstruct missing scores.

## Cross-assessment procedure
1. Define the construct in plain language before comparing instruments.
2. Record each assessment's finding and what it can legitimately measure.
3. Map constructs only when their definitions overlap; similar-sounding labels are not automatically equivalent.
4. Add behavioral evidence with source lineage. Repeated paraphrases of the same conversation count as one evidence family.
5. State agreement, disagreement, and missing comparisons separately. Do not average unlike scales or hide contradictions in a composite score.
6. Check context moderators such as role, stress, incentives, culture, language, familiarity, and task demands.
7. Generate competing mechanisms and observations that would distinguish them.
8. Set confidence based on quality, relevance, independence, recency, consistency and counterevidence—not the number of labels that agree.
9. Define a validation plan and update the map when new evidence arrives.

## How to use common instruments
- **Big Five:** potentially useful broad trait framework when instrument quality, version, scoring and norms are known. Trait scores are not destiny and do not establish skill.
- **MBTI:** can be used as a vocabulary for self-described preferences; do not treat type categories as precise measurements of ability or immutable identity.
- **DISC:** may structure a discussion of behavioral/work-style preferences; interpretation depends on tool quality and context.
- **Enneagram:** treat motivational explanations as hypotheses for reflection, not verified causal mechanisms.
- **Cognitive or decision tasks:** interpret only the abilities actually sampled, under the task's constraints. One task does not equal global intelligence.
- **Work samples and outcomes:** can support capability claims when tasks are relevant and performance is repeatable; account for opportunity, resources, teamwork and external constraints.
- **Interviews/self-report:** useful for goals, meanings and subjective experience; do not upgrade them to independent observations.
- **Astrology/numerology/symbolic systems:** separate `interpretive_only` lane; may prompt reflection but never support empirical claims or competence predictions.

## Required output sections
A complete map covers: context; personality; cognitive process; motivation/values; capabilities; behavior and execution; stress/recovery (non-clinical); environment/collaboration fit; strengths and costs by context; blind spots; contradictions/rival explanations; development direction; experiments; unknowns; and a longitudinal change log.

Every consequential claim must link to evidence and state claim class, confidence rationale, scope, counterevidence, alternatives and validation conditions. The map must be allowed to say "unknown" in any domain. Missing assessment results must never be filled by model intuition.

## Human-readable dashboard
Show:
- **What is observed** vs **what is inferred** vs **what remains unknown**
- Construct-by-construct agreement/disagreement matrix
- Evidence lineage and source independence
- Context-specific strengths and costs
- Hypotheses to test next, including disconfirming evidence
- Map version and what changed since the last version

The template at `templates/phm-human-map.template.json` is synthetic scaffolding, not a person profile.
